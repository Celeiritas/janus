## 0.3.1 – 2026-11-10
- **Contract rule: exit 0 always carries `user` and `node`.** Stated in `docs/contract.md` (the Zeus section). Today's checks already guaranteed it (a pass needs a device on the approvers' list and a login); `verify-approval` now also holds it as a last gate, so a config that lists a nameless device, or a future change, can never produce an `allowed` answer without both. ## 0.3.0 – 2026-11-09
- **`janus map`** (#11), the second face. One run asks `tailscale status --json` which devices exist and which are online, probes every door `doors.json` lists on the online ones (a TCP connect with a 2 s timeout; a GET of a `serve` door's health path; a Taildrop door is open while its device is online) and writes only what changed: `map.json` (version 1, the shape in `docs/plans/2026-11-09-map-page.md` §3.4), one `doors-YYYY-MM.jsonl` line per change, and argus-ui's alert file `alerts/janus.json` while a door that should be open is closed (removed in the run that finds it open again). A door is called closed only after two failed probes in a row; the first one waits in `run.json` in the runtime directory (memory), so a run that finds no change writes nothing to disk. A device Tailscale reports offline is never probed. `--json` prints the map, `--once` is the same run. Exit 0 when the run completed, 2 when Tailscale or `doors.json` could not be read (then nothing is written and the previous map stays)
- `map.json`, the doors log and the alert file hold **no tailnet addresses**: they are read from Tailscale on every run and never written (plan Q4). `docs/design.md` §6a and §8 say so now
- `config.load_doors()` reads `doors.json` alone, so a mistake in `routes.json` cannot stop the map
- `units/`: `janus-map.service` (one-shot), `janus-map.timer` (every 5 minutes) and the `argus-limits.conf` drop-in (CPU 25 %, 512 MB, nice 10). Nothing installs or enables them yet (#14)
- `janus-map.service` sets `TimeoutStartSec=60`. A one-shot unit has no start timeout of its own, so a run that hangs (a `tailscale` that never answers, a lock that never frees) would have kept every later timer run from starting. A run takes under 3 s; after 60 s systemd stops it and the next run starts as usual. Found in the review of the pull request
- Tests: `tests/test_mapper.py` (66 tests with the fake tailscale and local listeners: every state and probe text, the two-probe rule and its three exceptions, the alert file, a run with no change writing nothing, a failed run writing nothing, the status line, under 1 s with every door answering and under 3 s with every door silent, the unit files); the fake tailscale learns `JANUS_FAKE_STATUS=fail|garbage`; `load_doors` in `tests/test_config.py`
- CI runs on `ubuntu-24.04` (was `ubuntu-latest`), so a new runner image can't change a result unasked
- `docs/plans/2026-11-09-map-page.md` §7 "As built": what the build added to the plan, and blockers B3 and B4 answered

## 0.1.6 – 2026-10-21
- Tree arrivals (#8): `tree.py` checks a folder sent parted out (`data/<tree>` plus `manifest.json`, the format in `docs/contract.md`): check 1 once, checks 2–4 on every listed file with the failing file named ("setup.exe inside photos/"), climbing or hidden paths, backslashes and drive letters refused, symlinks anywhere under `data/` refused, holes (listed but missing) and strays (present but unlisted) refused, the manifest's hash against `meta.sha256` and the sizes' sum against `meta.bytes`; one verdict with `kind: "tree"` and a note counting the files; the duplicate rule uses the manifest's hash. `check.py` now judges files through one `Item`, so a single file and each file of a tree go through the same code. `docs/contract.md` written (Hermes ↔ Janus, both arrival shapes)

## 0.1.5 – 2026-10-21
- Archives by listing (#7): `archives.py` is the `archive-listing` shape rule. A zip is read by its central directory plus the first four bytes of each member; a tar or tar.gz by streaming its headers; nothing is extracted. Refused: a member that hits the executable rules (name or PE/ELF/Mach-O/`#!` content), a path that climbs or is absolute or has a drive letter, symbolic and hard links, an encrypted member, more than 50 000 members, a declared size over the route's (else the kind's) cap, or a declared size 100× the packed size from 1 MB up (the zip-bomb rule). Nested archives are counted into `notes` ("nested archives: 3 (not opened)") and never opened. `.7z`/`.rar` pass with the note "archive contents unchecked (.7z)" wherever the route lists `archive-opaque`

## 0.1.4 – 2026-10-21
- Integrity check (#6): the SHA-256 of `data` is recomputed in 1 MB chunks (never Hermes's hash) and compared with `meta.sha256`; the size on disk must equal `meta.bytes`. `seen.py`: SQLite `~/.local/share/janus/seen.db` (`$JANUS_STATE` names the folder) of hash → route, id, first seen; the same hash on the same route is a duplicate (exit 11); a pass records the hash; a corrupt store is exit 2, never a pass; `janus seen list` and `janus seen forget <hash>`. `log.py`: one line per check in `log/verdicts-YYYY-MM.jsonl` (design §5). With all four checks built, `janus check` now passes clean arrivals (exit 0)
